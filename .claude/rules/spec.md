# Maintaining the specification

Layout (`spec/README.md` is the index):

- `spec/log/`: the user's messages, verbatim (typos kept), **append-only**: an entry is never edited, moved or
  deleted. Entries go in one file per month, `spec/log/YYYY-MM.md`. An entry is
  `### L<id> · <date> · <title> (<kind>)`, an optional `Context:` line saying what it answers, then the message in a
  `text` fence.
- `spec/interpretations.md`: the J table (`| J<id> | Source | Interpretation |`), **append-only**. A J entry records a
  genuine interpretation only: what Claude reads into a message beyond its words. A J that is replaced stays; the
  current spec simply stops citing it.
- `spec/current/<area>.md`: the current specification, plain prose stating what is true now. Each rule has a stable
  area id (`LANG-4`) that is never reused, and a `Source:` line naming the L and J ids it rests on, saying which
  parts are interpretation. Superseded content is removed, not struck through: its history stays in the log, the
  J table and Git. An unresolved conflict is marked `[NEEDS USER: …]`, never resolved silently.

Ids: L and J ids are the minutes since 2026-01-01T00:00Z (or the latest id in use + 1 if higher), the next free one
on a clash, generated by `tooling/up spec-id L|J <latest id in use> [<count>]`, which reads the clock itself; never
pick one by hand. Ids are never renumbered. `tooling/up spec-check` validates ids, `Source:` references and the
append-only files; it passes before every commit that touches `spec/`.

Authority and the recording steps are in CLAUDE.md. The user does not review each area:
reviewer subagents check `spec/current/` against its sources (the spec reviewer of the code review, CLAUDE.md).
